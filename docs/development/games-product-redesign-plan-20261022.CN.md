# 六款发布游戏的体验审查与改造方案

[开发记录索引](README.CN.md) · [引擎修改方案](engine-improvement-plan-20261022.CN.md) · [游戏目录](../../examples/README.md)

日期：2026-10-22。审查基线：`37e1c538d7270bb7a2d7e63efd345a8e86ebddcd`。本次交付为修改方案，未实施玩法、美术或程序改造。

建议把六款产品分别定位为短局射击、布阵解题、平台冒险、互动景观、潜行撤离和街机竞速。优先解决“玩家在做什么、为什么成功或失败、能否舒服地操作”，然后围绕明确的玩法重做素材和实现。现有游戏名称、相机、地图、资产格式和渲染路径都可以调整；继续使用它们需要体验上的理由。

后续已经实施的修改和未完成项见[实施收敛记录](review-convergence-20261022.CN.md)。本文的产品建议及基线截图描述保留为评审依据。

## 1 范围、证据和判断边界

范围依据 [发布素材清单](../../release/asset_provenance.json) 与游戏目录：Raylib Shooter、Tower Defense、Sky Hop、Living Worlds、Last Zone Extraction、Neon Rift Rally。Tomb 和 benchmark 不作为本次发布游戏评审对象。

本次阅读各游戏中文说明、模型、输入模块、视图和素材配置，并重新构建六款 Host 模块，分别采集 480×480 与 320×240 的画面和状态。每种尺寸运行 360 个逻辑 tick；480×480 补入移动、跳跃、建塔、射击或竞速输入，Living Worlds 另切换四个场景。320×240 主要检查启动后的布局，Rally 另注入油门。运行长度和脚本动作只用于确定取证场景，不能代表完整游玩。

本地证据在 `artifacts/game-review-20261022/`，包含采集脚本、逐帧 PNG 和状态 JSON，按仓库约定忽略、不入库。历史 README 截图只作辅助，当前判断优先使用重新捕获的画面。Host 与 native 有输入、素材和渲染分支，尤其不能把 Living Worlds 的 Host 画面当成设备效果的完整证明。

本文分别标记三类结论：

- **已确认**：可由源码规则、说明文字或本轮画面直接核对。
- **体验风险**：由机制或画面推导，需要真人操作验证；不冒充用户研究结论。
- **改造提案**：可替换的设计方向，所列时长、尺寸和通过率是验收候选值，不是现有实测指标。

未做完整通关、长期留存测试、真人试玩、音频试听、设备触摸/IMU/震动验证，也没有板端 FPS、耗电或温升结论。本文不以主观分数给六款游戏排名。

## 2 产品组合与先做什么

| 游戏 | 已有价值 | 首要问题 | 推荐方向 | 改动深度 |

| Last Zone Extraction | 五地图、巡逻/警戒/协同 AI、补给与存档 | 撤离强制全歼；移动、转向、开火争夺两指输入 | 获取目标后自主撤离的小型潜行任务 | 先重做目标与控制；第一人称不成立时换俯视实现 |

## 3 跨游戏的共性问题

### 3.1 从玩家任务组织屏幕

当前多款游戏以 SCORE、SECTOR、TACTICAL SCORE、角度、连击等数值构成顶部 HUD。它们可以说明程序正在运行，却未必回答“这局要完成什么”和“下一步该做什么”。中文说明也不能替代设备内的教学。

每款游戏先画出完整流程：首次进入 → 选择或直接开始 → 一条操作教学 → 首次有效行动 → 首次失败 → 可理解的恢复 → 完成本局 → 再玩或退出。逐一补齐暂停、重开、结束后选择、记录保存和控制方式说明；不以模型里有某个 phase 作为流程完成的依据。具体游戏已有的存档要保留和迁移，不能把它们全部当成从零开始。

游戏内第一层仅放当前目标、紧急风险和必要资源；成绩、连击明细、AI 对手资料移到次要层或结算。结算解释一项可改进的行为，例如“有 3 架突击机漏过防线”，而非只显示总分。按钮和提示用玩家能理解的动词；为英文保留短标签，为中文规划真实字库、测宽和换行。

### 3.2 小屏应单独设计，素材不能只按原图判断

本轮 320×240 捕获中，Tower 已折叠商店到顶部，Sky Hop 也扩展了横向可视区域，说明存在适配工作；仍能看到顶部文字、塔型细节、远处车辆等明显缩小。不能把已有适配否定为纯缩放，也不能仅凭“不越界”宣布可用。

每款分别维护 480×480 和 320×240 构图草案，明确保留信息、触摸区域、手指遮挡区、危险进入视野的位置。字体以最终物理像素审查；可先以正文 12–16 像素、关键数值更大的范围试排，实际结果由屏幕尺寸与观看距离验证。触控目标按设备物理尺寸标定，不能直接套用浏览器 CSS 像素。

细纹理、金属高光和复杂背景应服从轮廓。敌人、可交互对象、危险与装饰通过形状、运动和明度共同区分，不能仅靠红绿颜色。HUD 不应盖住落点、射线目标或下一个弯道。给出低闪烁、可关闭震屏/震动的选项，并检查关闭后关键反馈仍能成立。

### 3.3 资产生产要围绕动作和状态

当前来源清单记录了图像及部分音频的生成来源；这不等于画面已具有统一的比例、光照、透视、动画和语义。允许整套替换，先出风格页和实际尺寸样张，再批量生产。

每个资产任务应包含：游戏用途、最终显示尺寸、视角/光照、调色板、透明边缘、动画状态、接地点或锚点、可见轮廓与碰撞体关系、低分辨率版本、来源与授权记录。生成图可以用作概念探索，进入游戏前仍需切帧、对齐、清理边缘和动作连续性检查。新外部字体、图片或音频需单独登记来源，现有素材清单不会自动覆盖它们。

音频已有 mixer、事件映射和部分反馈实现，后续重点应是混音与语义：危险提示优先于连续枪声，音量和静音可控，重复事件不会叠成噪声，暂停和重试不残留声音。设备试听与震感验收尚待执行，不能从文件存在推断听感。

## 4 Raylib Shooter：先决定射击的乐趣来自哪里

证据入口：[模型](../../examples/raylib_shooter/main/shooter_game.c)、[输入模块](../../examples/raylib_shooter/main/game_module.c)、[视图](../../examples/raylib_shooter/main/shooter_view.c)、[中文说明](../../examples/raylib_shooter/README.CN.md)。

### 已确认与体验风险

- 模型只有玩家弹丸，敌机以不同血量、速度和横向运动下降；说明中的“躲避弹幕”没有对应的敌方射击规则。当前主要任务是拦截与避碰，不能按成熟弹幕射击评价。
- 敌机飞过底边与碰到玩家都扣同一组生命。前者不受玩家碰撞无敌状态阻止。**风险**：玩家躲开敌机仍掉血，但画面上的 HULL 容易让人以为只代表自身装甲。
- 连击带来双发与更快射击，受伤或超时失去连击。**风险**：新手失误后火力下降，又更容易漏敌，需要检查失败是否形成难以恢复的循环。
- `shooter_game_set_pointer()` 把飞船直接放到手指附近，首次点击还同时开始游戏和改变位置。**风险**：手指盖住飞船，抬手重按产生瞬移，缺少稳定的操纵参照。
- 暂停画面写着 `TOUCH TO RESUME`，模型 pointer 分支却只处理开始、失败和进行中；ACTION 3 才切换模型暂停。恢复提示与触摸行为不一致，应优先修正。
- 波次每 450 tick 递增并封顶为 9，模型没有关卡胜利状态。敌机画面尺寸约 43–72，碰撞使用 28×28；小判定本身可以是设计，但需通过轮廓或弱点说明可击中范围。
- 当前背景星点、星云与敌机发光色相近。480 画面尚能读出飞船，320 画面更依赖轮廓；这是需要用动态样本验证的识别风险。

### 推荐方案：短局闪避射击

玩家用一指拖动、武器自动发射，完成三个短遭遇并击败一个有明确招式的终局敌人。首局目标约 90 秒：先教横移躲一列慢弹，再教从扇形弹间穿过，最后组合前两种规则。敌人差异首先体现在攻击节奏和预告上，再体现在血量。

主方案取消普通敌机漏出屏幕扣玩家生命，让闪避目标清楚；保留漏敌影响得分即可。若希望保留拦截身份，则改为“护送运输船”，玩家装甲和运输船完整度分开，给出漏敌方向提示。两个方向先择一做完整小样，不把两套处罚同时叠上。

触摸采用相对拖动和可调的上方偏移，首次按下建立锚点；可显示小型核心判定点。受伤后给足重新定位时间，火力保底，连击主要奖励分数或短暂强化。失败面板等待手指释放后再接受重试，避免连续触摸无意跳过结果。

美术可以整体改成“明亮的救援飞行器对暗色机械蜂群”：一艘轮廓独特的主机、三类靠外形识别的敌机、一个分阶段终局敌人、两类弹丸、统一爆炸与护盾动画、低对比背景。先让玩家弹、敌弹、奖励在 320 实际尺寸下无需读文字即可分辨，再决定是否保留现有精细金属质感。

**最小可玩版本与验收**：一个完整遭遇加终局；第一次触摸不跳位；暂停可仅靠触摸恢复；新玩家能说出掉血原因；危险来临前有可见预告；通关、失败、重试形成闭环。若有限关卡仍只剩横向追目标的机械劳动，继续改攻击模式，不先增加更多舰船。

## 5 Tower Defense：把“自动打怪”变成可理解的布阵选择

证据入口：[模型](../../examples/tower_defense/main/tower_game.c)、[视图](../../examples/tower_defense/main/tower_view.c)、[地图](../../examples/tower_defense/assets_src/level01.tmj)、[中文说明](../../examples/tower_defense/README.CN.md)。

### 已确认与体验风险

- 九个固定建造点、三类塔、固定路线提供了清楚的基础。视图已有射程圈、等级和建造结果反馈，不能称为完全没有预览或反馈。
- `handle_tap()` 在按下边沿直接操作：空位建造，同型升级，异型替换为一级并折算退款。玩家没有独立的“只查看这座塔”动作；已有射程显示也不能避免这次点击先花钱。
- 冰冻状态会使 PULSE 伤害翻倍、RAPID 加伤；代码判断的是同一目标的减速状态，没有塔的邻接判断。说明的“相邻不同类型形成组合增益”与实际规则不一致。
- 首波间隔 45 tick，后续间隔 75 tick；清完继续加波数、怪数与属性，模型没有有限关卡胜利。**风险**：新手缺少部署时间，也难分辨什么时候完成了一个好方案。
- 当前塔和敌人有细致金属纹理，三种商店图标却是简单几何图形。320 顶部布局虽然紧凑，但图标与场上实体的对应关系、路线入口和出口仍需强化。

### 推荐方案：六波一关的电站防守解题

部署阶段暂停出怪，先显示入口、出口、敌人路径和下一波组成。点建造点只选中；卡片显示成本、作用和射程，再按“建造/升级”确认。替换明确显示失去的等级、退款与净支出。部署期允许撤销最近操作，战斗期是否允许改建需单独定义，避免隐式惩罚。

关卡一只教“把塔放在能覆盖两段道路的位置”；关卡二教减速后集火；关卡三给两个入口，让玩家权衡集中与分散。每关约六波，有胜利、失败原因和重试入口；无尽模式可作为解锁后的附加内容。

保留现有基于敌人状态的连携，画面用结冰外壳、命中特效和短标签解释“先减速，再重击”。不为迎合旧说明额外硬加邻接规则。若希望更独特，可另做“接电线路决定塔供能”的小原型，验证布线是否比普通射程覆盖更有趣，成立后再替换战斗模型。

美术建议重做为可读的微型电站：统一斜俯视或正俯视，三塔分别以线圈、转轮、冷却罐识别，敌人以速度型/重甲型不同体形识别。地面降低噪声，路线有清楚的流向；商店图标来自对应塔的简化轮廓。必需资产是三塔各等级、三敌人行动/受击、供电核心、建造点、三种攻击与状态标识，无需先堆场景装饰。

**最小可玩版本与验收**：一张图、六波、至少两种可胜布阵；选中已有塔不花钱；资金不足能理解原因；玩家能解释减速连携，不必读技术说明；结算能定位漏怪路径。用固定种子比较方案，再用多种子检查单一阵容是否无脑最优。波次数值是待调方案，不是现有平衡结论。

## 6 Sky Hop：让已有跳跃手感服务一个有辨识度的冒险

证据入口：[模型与四关布局](../../examples/sky_hop/main/platform_game.c)、[视图](../../examples/sky_hop/main/sky_hop_view.c)、[素材配置](../../examples/sky_hop/assets_src/atlas.json)、[中文说明](../../examples/sky_hop/README.CN.md)。

### 已确认与体验风险

- 已有土狼时间、跳跃缓冲、松手截短跳跃、踩踏、连击、弹簧、检查点、受伤无敌和粒子反馈；不能把“添加这些机制”当成下一轮主要工作。
- 四关不是纯换色：第一关有连续地面，后续关卡已有间隙、不同平台、敌人和弹簧配置。不过第一关高处路线主要由金币吸引，地面可以绕过不少跳跃挑战；终点判定不要求收集金币。
- 后续关卡主要通过间距、平台高度、敌人速度和地面缺口递进。**风险**：天气主题与玩法记忆点的联系偏弱，玩家记住的可能是更难的同一关。
- 480 捕获中，眼镜人物的面部/服装细节、土块像素素材、低细节山景属于不同的视觉语言。角色未必必须换，但需要统一比例、描边、像素密度与动作夸张程度。
- 底部三个半透明控件覆盖地面区域，模型触摸动作区从设计坐标 y=360 开始，比可见按钮更高。**风险**：玩家既要在此看脚下和落点，又要把手指放在这里，且可能触发未显式标出的区域。

### 推荐方案：云间送信的短篇平台冒险

主角可以改成轮廓简单的小邮差或滑翔生物；若眼镜人物是项目身份，则把整套世界按其风格重画。核心仍是“助跑、起跳、空中修正、落地”，先保持已有宽容机制，用一段 2–3 分钟的关卡建立角色、目标和节奏。

第一段在安全地面教短跳/长跳；第二段让弹簧连到高处捷径；第三段加入一种会改变路线的机关并到达明确的投递点。主路可稳定完成，支路给邮票或更快路线，奖励可用于关卡完成度和角色装饰。不要为强迫跳跃而把所有金币改成硬性通关钥匙。

主题机制先选一种做透，例如风场托举；用可见的风带说明方向，安全区先演示，再与弹簧组合。其他主题以后再分别选择坍塌平台、滑面或升降台，不一次引入全部。失败从最近检查点快速恢复；可将无限检查点重试设为普通模式，把现有有限生命留给挑战模式。

为触屏分别比较“左右加跳跃”和“横向滑动加独立跳跃”两个样机，以误触与落点控制选择，不预设自动跑更好。相机应预留前方和下方的危险观察空间，控件区与主要落点分离；画面按钮、捕获区域和取消规则一致。

美术最小集：主角待机/跑/起跳/下落/落地/受伤，统一地表边缘与平台底面、一个敌人的走动/预备攻击/受击、一种机关、投递点与检查点。先保证角色脚底与碰撞体一致、地面和背景可区分，再做四季背景扩展。

**最小可玩版本与验收**：一关包含教学、选择、变化和结束；无需读长说明也能学会短长跳；手指不遮住关键落点；失误后能说明“按晚了/高度不足/被敌人撞到”；支路有吸引力但不阻断主路。保留现有物理作为对照，用真人试玩决定是否重写运动模型。

## 7 Living Worlds：可以成为好产品，不必硬变成计分游戏

证据入口：[世界与交互模型](../../examples/living_worlds/main/living_worlds_world.c)、[视图](../../examples/living_worlds/main/living_worlds_view.c)、[Ocean](../../examples/living_worlds/main/living_worlds_ocean.c)、[Aurora](../../examples/living_worlds/main/living_worlds_aurora.c)、[中文说明](../../examples/living_worlds/README.CN.md)。

### 已确认与体验风险

- Ocean/Aurora 已有点按和拖动响应，并非四张完全静态背景；Sunrise 与 Rainforest 没有同等的点按内容响应。场景间交互承诺不一致。
- README 称四场景 360° 环视，模型对 Aurora/Ocean 的视角有限制，Sunrise 在很小的视锥内移动，Rainforest 才使用 wrap-around yaw。应改成真实的场景能力说明，或重新制作满足完整环视的素材。
- 停止操作后约 90 tick 开始恢复各自的自动运动。**风险**：用户想停留观看一个位置时，镜头会重新移动；对桌面观景来说这可能比少一个特效更影响使用。
- 顶部 FX/角度和底部四场景标签长期占据画面；顶部较大区域点按会切换 effects_level。**风险**：技术参数先于内容，且隐藏的热区不易发现。
- 当前 Ocean 捕获有细密岩石、光束和半透明水母，氛围鲜明，但生物与装饰边界不总清楚。源码与画面尚不能证明每种点击都有可理解的因果。

### 推荐方案：可驻留的互动微景观

先完成一个“会回应的小世界”：拖动轻微改变视点，点水面产生涟漪，点生物引起明确行为，长时间不操作进入自然演出。交互后保留用户选择的视点，自动巡游作为明确开关；界面渐隐，轻触唤回，场景切换有明确入口。

保留环境声、独立音量、最后场景和视点偏好；加入低动态模式。每个场景定义两到三个可见且不同的响应，避免随处点击都只有同一种粒子。先使一场景完整，再扩展到四场景。

可以放弃完整 360°，将素材重构为背景、远中近景、遮挡层、交互对象和少量动态光效，用 2.5D 视差完成精致的微景观。若真正需要环视，则要求全景接缝、投影、视点边界和主体遮挡一起验收，不用一张漂亮图片承担未设计的自由相机。

如果需要更强的游戏性，单独验证“自然观察手册”：发现三个行为、等待一个时刻、拍下一张图景即可完成一页；不强制限时和连击。这是另一个产品方向，应先验证玩家是否愿意观察，而不是把任务框叠到所有场景上。

美术先选统一的绘本或风格化自然主题，把可交互对象做成独立动画资产；降低非主体高频纹理，为运动留出空间。声音与画面事件对应，自动场景变化不应突然变响。**最小验收**：一场景连续驻留、UI 隐藏/唤回、视点保持、三种可理解交互、切换与恢复均成立；长期驻留的内存、耗电和温升另做设备测试。

## 8 Last Zone Extraction：先让“撤离”成为真正的选择

证据入口：[模型](../../examples/last_zone_extraction/main/last_zone_game.c)、[输入](../../examples/last_zone_extraction/main/game_module.c)、[视图](../../examples/last_zone_extraction/main/last_zone_view.c)、[存档](../../examples/last_zone_extraction/main/last_zone_save.c)、[原生入口](../../examples/common_components/examples_common/native_module_main.c)。

### 已确认与体验风险

- 五地图与巡逻、怀疑、视野、警戒传播、侧翼/重装角色等机制已存在。主要问题不是缺 AI，而是这些机制服务什么目标。
- 胜利条件是 `last_zone_enemies_alive(game)==0 && last_zone_on_extract(game)`。玩家可以借潜行取得战术优势，但最终必须清光敌人，无法选择避战完成撤离。
- 开火输入支持按住稳枪、松开发射；`last_zone_fire()` 还会优先处理前方门。**风险**：玩家预期的“按下开枪”与“松开发射/面对门变成开门”不同，缺少明确提示会被理解为输入不灵。
- 模块分别捕获移动、看向、开火和雷达拖动 track；原生公共入口请求两触点。移动、看向、独立开火三种持续角色无法同时占用三个手指。玩家仍能分时操作，但不能把这种限制当成自然的 FPS 手感。
- 480/320 当前捕获呈现写实海景、墙面、地面和前景枪械，敌人及 HUD 在小屏上的读法依赖另外的风格和比例。**风险**：真实纹理密度压过目标和路径辨识，远敌、开口和危险方向不够突出。

### 推荐方案：三分钟级别的潜入、取物、撤离

首个任务只包含一个目标物、两条路线、一个巡逻组和明确出口：进场观察 → 选择绕行或交火 → 获得目标 → 触发新的风险 → 自主抵达撤离点。清敌是可选策略，奖励也应承认未被发现和节省资源。先用固定任务验证，再决定是否需要随机地图或局外养成。

先做两个可比较的控制原型：

1. 第一人称保留水平瞄准辅助，左指移动；右指拖动瞄准，在同一捕获区域内完成短按射击或松手射击，明确解释并容许取消。开门/拾取使用清楚的上下文提示与动作，不隐式占用开火。
2. 俯视潜行撤离：点目标移动或左指方向控制，视锥直接呈现；点敌人选择攻击，点门互动。允许暂停规划，把内容重心转向路线、警戒和资源选择。

推荐先验证第一种，复用已有 AI 与地图；如果两指操作仍无法让新人稳定完成“移动中瞄准并发射”，则转向第二种。视角和 raycast 实现都可以替换，不能因技术投入而持续保留体验负担。比较标准是完成任务和解释失败的能力，不是截图更像大型 FPS。

美术建议从照片拼接转为统一的风格化港口：大色块标记仓库、码头、出口，敌人用姿态和轮廓表达角色，警戒用形状/动画/声源共同提示。枪械缩小到不遮住近处交互对象；墙体和地面降低纹理频率。首版只需一套墙地、三个地标、一种武器、两类敌人与完整警戒状态、目标物和出口标识。

**最小可玩版本与验收**：一张图可用避战和交火两种方式完成；两指完成核心动作；门不会造成意外的开火语义变化；受击能判断方向；失败后从明确的任务状态重试；已有进度存档在规则变化后有版本迁移或明确重置策略。尚不承诺俯视方案一定更快，性能须分别在目标板采集。

## 9 Neon Rift Rally：保留速度感，减少玩家同时解释的规则

证据入口：[竞速模型](../../examples/neon_rift_rally/main/rally_game.c)、[输入](../../examples/neon_rift_rally/main/game_module.c)、[视图](../../examples/neon_rift_rally/main/rally_view.c)、[镜头运动](../../examples/neon_rift_rally/main/rally_view_motion.c)、[中文说明](../../examples/neon_rift_rally/README.CN.md)。

### 已确认与体验风险

- 已有三赛道、三圈赛、六个 AI 对手、氮气、尾流、近失、漂移辅助、对手信息、检查点与成绩保存。它已不缺机制清单。
- 原生默认自动加速；Host ACTION 需要油门或触摸驾驶输入。本轮首次脚本只注入左右转向时车辆保持零速，加入 ACTION 2 后正常行驶。这是输入配置差异，不能误报为赛车无法前进，也说明回放与教学必须注明控制模式。
- 倒计时校准 IMU、触摸转向与键盘漂移各有分支。**风险**：玩家不一定知道当前哪种输入生效，设备放置姿态和手持姿态改变时缺少明显的重新定中入口。
- 主界面包含名次、圈数、分数、rival、速度、氮气和中央事件提示。**风险**：尾流/近失/漂移奖励在激烈转向时抢占阅读注意；更丰富的反馈未必让驾驶更清楚。
- 当前画面已有鲜明霓虹方向，但摩托细节、远车像素、道路几何和高对比场景建筑的层级仍需统一。碰撞、越界与转弯的可预判性需要动态试玩，不能仅凭静帧断言公平或不公平。

### 推荐方案：先做一条读得懂、愿意再跑的短赛道

首局只教转向和氮气，采用自动加速，一圈约 60–90 秒作为调参目标。弯前给稳定的方向与曲率提示，直道演示尾流补能；入门局避免同时要求手动漂移、精细刹车和撞击管理。完整三圈赛和高级控制作为后续挑战。

进入倒计时前选“倾斜”或“触摸”，给一个可见的转向试验区，明确中立位置和重校准入口。接管时规定触摸与 IMU 的优先级，松手平滑恢复。按真实设备验证横向握持、手指遮挡与失联恢复。

竞速中只把名次、进度和氮气留在强视觉层，积分和竞争事件减弱或延后显示。危险反馈优先于得分，中央提示避开前方赛道；同类事件合并，避免连续横幅。碰撞后有可预测的恢复，失败说明越界/撞击原因；AI 追赶策略需要回放比较，不能让努力提升的驾驶被无解释地抵消。

美术可保留霓虹主题，但统一摩托五向倾斜姿态的尺寸、轮胎接地点和光源；远车采用特制简化轮廓，不依靠高细节原图缩小。道路边线、弯道护栏和路标的对比高于装饰霓虹，坡顶提前提示落点。若现有道路表现难以保证这些读法，可比较更简洁的 2.5D 道路与固定镜头，不以“几何更复杂”作为质量目标。

**最小可玩版本与验收**：一条短赛道、两种控制模式、清楚的起跑和结束；初次玩家能完成一圈并理解一次失误；关闭分数横幅后信息不缺失；重复回放能比较路线与成绩；校准、暂停恢复、重新开始无控制残留。帧率、晕动与震感均待板端验证。

## 10 新素材与实现的决策门槛

| 对象 | 优先保留的价值 | 可以直接推翻的部分 | 批量生产前的验证 |
| --- | --- | --- | --- |
| Shooter | 一指自动射击、短反馈循环 | 敌机行为、扣血规则、舰船/背景全套 | 用方块做出有节奏的闪避遭遇，再用一套样张验证辨识 |

| Living Worlds | 氛围与直接响应 | “四场景都 360°”、投影/体积实现、素材分层 | 一个场景驻留和交互成立，确定相机范围再画背景 |

每次替换留下可比较的旧版回放与截图，记录改善的是哪项体验。新美术不能靠提升分辨率掩盖轮廓问题；新实现也不能靠 Host 跑得快证明适合设备。原型可以在游戏内部自由尝试，稳定后再决定哪些能力适合抽为共享层。

## 12 可执行的修改清单与验收

### 第一批：恢复操作与说明的可信度

| ID | 修改任务 | 完成标准 |
| --- | --- | --- |
| GAME-01 | Shooter 触摸暂停/恢复与提示一致，开始/重试等待明确手势 | 全流程仅靠触摸可完成，按住不自动跳过结果 |
| GAME-02 | Tower 选中与花钱分离；连携说明对齐真实规则 | 查看不扣钱，替换展示净成本，说明能对应模型 |
| GAME-03 | Living Worlds 视角能力说明、固定视点与巡游开关 | 每场景可预期，不再对全部场景笼统承诺 360° |
| GAME-04 | Last Zone 两指控制原型与撤离目标原型 | 用真实双指完成任务，不需要第三个持续触点 |
| GAME-05 | Rally 控制模式与 Host 回放参数明确 | 教学、自动油门、IMU 与回放使用同一份模式定义 |
| GAME-06 | 六款双尺寸 HUD、控件和中文样张 | 危险区无遮挡，文案可读，字库覆盖，无静默缺字 |

### 第二批：每款一个完整体验样板

依次落实上述六款的最小可玩版本。每次只验证一个核心变化：Shooter 的闪避节奏、Tower 的布阵选择、Sky Hop 的路线乐趣、Living Worlds 的驻留体验、Last Zone 的自主撤离、Rally 的驾驶可预判性。每款样板明确“保留/修改/放弃”结论后才生产更多关卡与素材。

试玩建议先邀请 5–8 名没看过代码和说明的人，观察首次 3 分钟以及一次失败后的再尝试；该规模用于发现明显问题，不能推断总体留存。记录首次有效动作时间、误触、失败原因解释、是否主动重试、素材识别混淆。观景产品改记是否发现交互、能否停在想看的位置、是否愿意驻留，不套用射击游戏的胜负指标。

可以暂定“至少 4/5 受试者无需口头指导完成核心动作”作为首轮门槛；未达到先改教程、布局或规则，不靠继续加特效弥补。每款保留具体观察记录，不能用问卷里的“还不错”替代操作证据。

### 第三批：验证后扩量与设备验收

内容扩展从验证过的规则组合产生，避免只换背景加血量。为每款列出各关首次引入的机制、组合方式、休息段与终局。素材预算用像素格式、尺寸、帧数、音频时长和同时驻留量计算，再测峰值；不要先统一拍一个适用于全部游戏的内存或 FPS 数字。

后续实施时按改动选择检查：模型/CLI/公共 C 跑相关 focused tests，再按仓库要求跑完整 unittest；光栅改动跑独立 pixel oracle 并先比较画质；素材转换跑 packer/game 测试和 manifest 名称校验；音频/震动检查事件重复消费与清理并上设备试听/体验；板适配构建对应目标，用独立 build 目录验证启动、输入、present、暂停恢复与退出。刷机、安装和发布另需授权。

形成本文时的文档验收：维护 Markdown 链接检查、文档发布边界测试和 `git diff --check`；六款 Host 双尺寸构建与截图用于取证。没有修改游戏 C、资产源文件或发布清单，不以文档检查替代后续实现验证。
