## Step 1：建立游戏平台与交互原型

**主要时间：2026-09-04 至 09-07。**

### 做了什么

- 建立 Raylib 游戏平台和设备工作流。
- 升级 Sky Hop，加入可交互的 Host 预览。
- 将固定逻辑更新与显示提交解耦，避免显示节奏改变游戏速度。
- 建立通用 Host 游戏仿真协议，减少预览帧编码造成的停顿。
- 加入 Scene、UI、FX、版本化存档等早期游戏 SDK 能力。
- 加入可复现设备 benchmark 模式。

### 阶段结果

有了游戏生命周期、交互预览和测量入口。此时重点是游戏能跑、能操作、能观察，尚未完成后来的中性 Engine/Board 边界。

部分早期 SDK 抽象后来未被维护游戏采用；“已经实现”不等于“已经证明复用价值”。

代表提交：`449d437`、`c94ae32`、`d4bf422`、`72a0a1c`、`2df69e0`、`53b67eb`。

## Step 2：共享游戏源码，建立独立 Engine 仓库

**主要时间：2026-09-14 至 09-15。**

### 做了什么

- 建立共享源码的 Raylib 仿真路径，统一设备与当时的 GSP 仿真运行方式。
- 将 GSP 预览变成显式模式，收敛为一个通用 Host simulator。
- Sky Hop 的模型由 Host 与设备共享，避免两份玩法实现分别维护。
- 升级 Mosaico Strike、Sky Hop 渲染和 IMU 操作等实际游戏能力。
- 从 ESP-Mosaico Vibe 抽出复用的游戏运行时与工具，建立 Raylib Lite Engine 仓库并保留历史。
- 修正安装根目录解析、首次编译前资源准备和 Windows 编译器/DLL 生命周期。

### 阶段结果

开始形成独立 Engine 的开发入口。历史提取版本仍使用 `mosaico_*` 名称，并涉及 GSP、Iris 等当时的集成路径；这些不是当前全部仍受支持的工作流。

[Changelog](../../CHANGELOG.md) 将初次提取记为 `0.1.0 - 2026-09-15`，不据此推断当时完成了 Registry 发布或所有设备验收。

代表提交：`6d4e56f`、`eb4525e`、`bc38d1e`、`bc29b29`、`95372ba`、`06cb81a`。

## Step 3：发展专用渲染、资源能力和多游戏验证

**主要时间：2026-09-16 至 09-26。**

### 做了什么

- 增加 raycast column、span、floor-row、墙柱批处理等专用绘制路径。
- 优化 RGB565 填充、复制、着色及通用图元。
- 增加纹理三角形与四边形光栅，使用 16 级光照查找表。
- 导入 Living Worlds、Last Zone、Tomb 等游戏与开发指南，扩大真实负载范围。
- 增加 INDEX8 墙面资源、内存资源能力和 MTX2 压缩纹理实验。
- 进一步分离 `logic_hz` 与 `target_fps`，加入固定回放和 framebuffer 写入形态统计。
- 开展游戏级性能实验：缓存重复计算、递推三角函数、删除冗余全屏清除。

### 阶段结果

引擎的差异化能力逐渐明确：游戏通过 raylib 风格接口使用自有光栅，重负载还可直接使用墙柱、地板和 INDEX8 等扩展。

Living Worlds 的历史实验记录了以下板端 A/B：

| 场景 | 初始显示 FPS | 实验后显示 FPS | 记录中的提升 |
| --- | ---: | ---: | ---: |
| Aurora | 24.58 | 26.23 | 6.7% |
| Ocean | 15.73 | 19.30 | 22.7% |
| Sunrise | 18.00 | 21.27 | 18.2% |

这些是2026-09-26 历史实验，不是当前发布固件的验收结果。MTX2 也仍属于有工具与测试、尚未接入维护游戏普通绘制路径的实验能力。

代表提交：`d415500`、`1113738`、`d4d6fd6`、`686826a`、`04f5c7f`、`b29e3aa`、`84ea4f5`、`e4ab920`。

## Step 4：建立中性接口、板级边界与独立交付流程

**主要时间：2026-09-28 至 10-09。**

### 做了什么

- 整理 Engine 契约、双语文档、Agent 检查规则和 benchmark 工作流。
- 将产品侧 Iris/Recovery 等职责与 Engine、原生例程的职责分开。
- 统一 `raylib_lite_*` 中性命名，把 Raylib 类型与名字映射隔离到 `compat/raylib/`。
- 收敛共享游戏模块与 Board 契约，移除游戏对具体板级实现的依赖。
- 增加 ESP32-S3-BOX-3 Board Manager 适配及相关输入、音频验证记录。
- 修正首次帧接受、异步显示统计和音频句柄控制等生命周期问题。
- 建立独立 Registry component 与例程组装：各例程带自己的共享 launcher 和 Board，不依赖相邻源码目录。
- 恢复 Neon Rift Rally 并加入七个维护游戏的发包集合。
- 加入发布消费者构建检查、BMGR 配置生成和 CI 流程。
- 优化三角形扫描线、不透明着色缩放和 Neon 道路采样缓存。

### 阶段结果

仓库开始具备明确的层次：Engine、兼容层、共享游戏、Board 与产品部署各有边界。支持哪些设备路径，要看具体构建与设备证据，而不是仅看组件版本约束。

Neon Host 优化记录中，18 个固定状态的绘制耗时均值从 1.052 ms 降到 0.427 ms，减少 59.5%；这是当时的 Host CPU 对照，不是设备 FPS，也不是连续玩法的帧时间分布。

代表提交：`d306f71`、`b9a21c4`、`0d0b4df`、`3d50935`、`b3cc8bd`、`1c0ca95`、`b93c2ae`、`3214826`、`dd61ae9`、`2c35c74`、`a81c769`。

## Step 5：校准兼容语义，建立自有与上游路径对照

**主要时间：2026-10-10 至本次整理。**

### 做了什么

- 冻结 raylib 映射名单，逐项登记“契约、等价、差异”。
- 将上游 raylib + rlsw 接到本仓库的平台契约上，提供原生接入和对照路线。
- 明确兼容路径与原生 rcore 路径不能在同一游戏中混用纹理句柄。
- 修正三角形共享边、圆角填充重复混合与 `TextFormat` 缓冲语义。
- 改善默认文字的字形、字号与测量，以及半透明纹理和旋转采样。
- 扩展 stack benchmark，覆盖文字、相机、裁剪和 tilemap。
- 形成 Host 像素对照、S31 历史离屏与修正后 S3 离屏记录。
- 本次回顾七个维护游戏的消费者，区分实际使用、实验能力和备用路线。

### 阶段结果

[兼容层记录](../raylib-compat.CN.md)给出了画质、耗时和内存证据，同时明确了证据范围：

| 已有证据 | 支持的结论 | 当前限制 |
| --- | --- | --- |
| S31 历史三场离屏对照 | 自有光栅在这些场景耗时低于上游路径 | 早于文字/纹理修正，不含面板送数 |
| 修正后 S3 三场离屏对照 | 有当前实现的设备算力对照 | 480×480 下三场兼容路径均超过约 33 ms，不是 BOX-3 上屏验收 |
| Host 整帧像素对照 | 文字/纹理修正减少已测场景差异 | 不代表完全等价或设备 FPS 提升 |

当前七个发包游戏均使用兼容层，其中部分直接使用专用渲染扩展。只有 Sky Hop 使用 `BeginMode2D`，旋转固定为 0；现有游戏没有旋转文字需求。Scene/UI 尚未被这七个游戏采用，但未做外部消费者审计，不能直接认定可以删除。

代表提交：`9b9aa09`、`b16dfff`、`3180fad`、`40b497a`、`ffb618d`、`d74a6e6`、`907c758`。
